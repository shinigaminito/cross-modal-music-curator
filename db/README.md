\# спецификация базы данных и структуры хранения



в данном каталоге приведено описание даталогической структуры реляционной базы данных sqlite (`music.db`), используемой в системе кросс-модального подбора музыки\[cite: 2, 4]. база данных объединяет каталог музыкальных композиций с психоакустическими признаками spotify и журнал телеметрии пользовательских оценок\[cite: 2].



\---



\## 1. источники данных и объемы

\* \*\*коллекция треков:\*\* сформирована путем интеграции, очистки и дедупликации открытых наборов данных платформы kaggle (`spotify\_1million\_tracks` и `spotify 1.2m+ songs`)\[cite: 2, 3].

\* \*\*общий объем каталога:\*\* более 2 500 000 музыкальных композиций с предвычисленными психоакустическими дескрипторами\[cite: 2].

\* \*\*целостность признаков:\*\* все отсутствующие или поврежденные числовые значения при загрузке нормализуются с дефолтным коэффициентом 0.5\[cite: 4].

\* \*\*формат хранения:\*\* реляционная субд sqlite (файл `src/music.db`)\[cite: 2, 4].



\---



\## 2. даталогическая схема (таблицы базы данных)



\### таблица `tracks` (каталог музыкальных композиций)

основная таблица, используемая алгоритмом гибридного векторного ранжирования для подбора релевантных треков\[cite: 2].



| поле | тип | ограничения | назначение |

|---|---|---|---|

| `track\_id` | TEXT | PRIMARY KEY | уникальный идентификатор композиции в экосистеме spotify\[cite: 2] |

| `artist\_name` | TEXT | NOT NULL | имя исполнителя / название музыкального коллектива\[cite: 2] |

| `track\_name` | TEXT | NOT NULL | наименование музыкальной композиции\[cite: 2] |

| `genre` | TEXT | - | жанровая категория (используется для нечеткого жанрового буста)\[cite: 2, 4] |

| `popularity` | REAL | CHECK (>= 0.0) | нормализованный индекс популярности трека на стриминговой платформе\[cite: 2, 4] |

| `year` | INTEGER | - | год релиза композиции\[cite: 2] |

| `valence` | REAL | NOT NULL, CHECK (0.0..1.0) | эмоциональный тон (музыкальный позитив)\[cite: 2, 4] |

| `energy` | REAL | NOT NULL, CHECK (0.0..1.0) | воспринимаемая интенсивность и динамика трека\[cite: 2, 4] |

| `danceability` | REAL | NOT NULL, CHECK (0.0..1.0) | ритмическая стабильность и танцевальность\[cite: 2, 4] |

| `acousticness` | REAL | NOT NULL, CHECK (0.0..1.0) | степень акустического (не электронного) звучания\[cite: 2, 4] |

| `instrumentalness`| REAL | NOT NULL, CHECK (0.0..1.0) | вероятность отсутствия вокальной партии\[cite: 2, 4] |

| `key` | TEXT | - | музыкальная тональность\[cite: 2] |

| `loudness` | REAL | - | общая громкость трека в децибелах (db)\[cite: 2] |

| `mode` | TEXT | - | лад композиции (мажор/минор)\[cite: 2] |

| `speechiness` | REAL | - | присутствие разговорной речи в треке\[cite: 2] |

| `liveness` | REAL | - | вероятность концертного (live) исполнения\[cite: 2] |

| `tempo` | REAL | - | темп композиции в ударах в минуту (bpm)\[cite: 2] |

| `duration\_ms` | INTEGER | - | продолжительность трека в миллисекундах\[cite: 2] |

| `time\_signature` | TEXT | - | музыкальный метр (размер такта)\[cite: 2] |



> поля `valence`, `energy`, `danceability`, `acousticness` и `instrumentalness` формируют пятимерный вектор $V \\in \\mathbb{R}^5$, по которому вычисляется метрическое сходство с вектором изображения\[cite: 2, 4].



\---



\### таблица `ratings` (пользовательская обратная связь и телеметрия)

служит для накопления обучающей выборки, оценки качества рекомендаций и проведения статистического анализа\[cite: 2].



| поле | тип | ограничения | назначение |

|---|---|---|---|

| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | уникальный идентификатор записи лога\[cite: 2, 4] |

| `timestamp` | DATETIME | DEFAULT CURRENT\_TIMESTAMP | дата и время фиксации оценки\[cite: 2, 4] |

| `rating` | INTEGER | CHECK (1..5) | субъективная оценка релевантности подбора от пользователя\[cite: 2, 4] |

| `valence` | REAL | NOT NULL, CHECK (0.0..1.0) | расчетная валентность анализируемого изображения\[cite: 2, 4] |

| `energy` | REAL | NOT NULL, CHECK (0.0..1.0) | расчетная энергичность анализируемого изображения\[cite: 2, 4] |

| `danceability` | REAL | NOT NULL, CHECK (0.0..1.0) | расчетная танцевальность анализируемого изображения\[cite: 2, 4] |

| `acousticness` | REAL | NOT NULL, CHECK (0.0..1.0) | расчетная акустичность анализируемого изображения\[cite: 2, 4] |

| `instrumentalness`| REAL | NOT NULL, CHECK (0.0..1.0) | расчетная инструментальность анализируемого изображения\[cite: 2, 4] |

| `hue` | REAL | NOT NULL | средний цветовой тон кадра в диапазоне \[0.0, 1.0]\[cite: 2, 4] |

| `saturation` | REAL | NOT NULL | средняя насыщенность кадра в диапазоне \[0.0, 1.0]\[cite: 2, 4] |

| `brightness` | REAL | NOT NULL | средняя яркость кадра в диапазоне \[0.0, 1.0]\[cite: 2, 4] |

| `description` | TEXT | - | текстовая семантическая интерпретация сцены от модели vlm\[cite: 2, 4] |

| `tracks\_json` | TEXT | NOT NULL | сериализованный json-массив выданных рекомендаций\[cite: 2, 4] |

\## 3. архитектурные особенности хранения

\* \*\*денормализация выдачи (`tracks\_json`):\*\* сохранение результирующего списка треков в виде сериализованного json исключает необходимость выполнения тяжелых объединений (join) при аудите сеансов анализа и гарантирует неизменность исторического контекста подбора\[cite: 2].

\* \*\*индексация:\*\* для оптимизации селективности при нечетком поиске по жанровым тегам и фильтрации созданы индексы `idx\_tracks\_genre` и `idx\_tracks\_popularity`.

\* \*\*миграции:\*\* при старте веб-сервера вызываются автоматические процедуры `init\_feedback\_db()` и `migrate\_db()`, обеспечивающие валидность структуры таблицы обратной связи без прерывания работы приложения\[cite: 4].
