\# Cross-Modal Music Curator (Интеллектуальная система подбора музыки по изображению)



Клиент-серверная система кросс-модального поиска, транслирующая визуально-семантические и колористические дескрипторы изображений в 5D-психоакустический профиль треков (стандарт Spotify) для автоматизированного подбора релевантного музыкального сопровождения.



> \*\*Роль в проекте:\*\* Системный аналитик / Архитектор решения  

> \*\*Стек:\*\* FastAPI, Python, PyTorch, Qwen2.5-VL (4-bit NF4), SQLite, REST API, OpenAPI/Swagger, UML, PlantUML.



\---



\## 1. Бизнес-контекст и решаемая проблема

\* \*\*Проблема:\*\* Ручной подбор музыкального сопровождения для визуального контента в маркетинге, дизайне и медиапроизводстве ресурсоемок, субъективен и подвержен семантическому разрыву между визуальной эстетикой и звуком.

\* \*\*Цель системы:\*\* Обеспечить автоматизированный поиск и ранжирование готовых лицензионных треков из каталога (2.5M+ композиций) по загруженному изображению менее чем за 30 секунд на потребительском оборудовании.

\* \*\*Эффект:\*\* Сокращение времени подбора трека с 10–15 минут до \~24 секунд при 85% положительных пользовательских оценок (4-5 звёзд).

\## 2. Функциональные и нефункциональные требования



\### Функциональные требования (FR)

1\. \*\*FR-01:\*\* Валидация входных изображений (форматы JPEG/PNG, размер до 10 МБ, конвертация в RGB).

2\. \*\*FR-02:\*\* Экстракция низкоуровневых колористических характеристик (палитра 5 доминирующих цветов в HEX, средние значения каналов HSV).

3\. \*\*FR-03:\*\* Семантический zero-shot анализ визуального ряда с использованием VLM (Qwen2.5-VL-3B-Instruct) с детерминированной генерацией JSON-дескрипторов.

4\. \*\*FR-04:\*\* Формирование 5D-психоакустического вектора $V = \[v, e, d, a, i] \\in \[0; 1]^5$ (Valence, Energy, Danceability, Acousticness, Instrumentalness) через гибридную трансляцию.

5\. \*\*FR-05:\*\* Векторный поиск и гибридное ранжирование кандидатов (косинусное сходство + евклидово расстояние + нечеткий жанровый boost + индекс популярности).

6\. \*\*FR-06:\*\* Экспорт результатов в CSV-плейлист и генерация брендированной визуальной JPEG-карточки 1080×1080.

7\. \*\*FR-07:\*\* Сбор и денормализованное логирование пользовательских оценок (1–5 звезд) для валидации качества модели.



\### Нефункциональные требования (NFR)

\* \*\*NFR-Performance:\*\* Полное время цикла обработки одного запроса $\\le 30$ сек (факт: $24.57 \\pm 1.79$ с).

\* \*\*NFR-Hardware:\*\* Потребление видеопамяти (VRAM) в пике $\\le 4$ ГБ (факт: 3.01 ГБ за счет квантизации NF4).

\* \*\*NFR-Concurrency:\*\* Потокобезопасный доступ к ресурсам GPU при многопользовательском режиме (механизм `asyncio.Lock()`).

\* \*\*NFR-Usability:\*\* Асинхронная неблокирующая архитектура с механизмом опроса статуса (polling) каждые 1.5 сек.

\## 4. Алгоритмическое ядро: Гибридный метод ранжирования



Итоговый показатель соответствия трека формируется по формуле взвешенной агрегации:

$$Score\_{total} = 0.75 \\cdot S\_{hybrid} + 0.15 \\cdot S\_{genre} + 0.10 \\cdot P\_{norm}$$



Где:

\* $S\_{hybrid} = 0.7 \\cdot S\_{cos} + 0.3 \\cdot \\frac{1}{1 + d}$ — гибридное метрическое сходство в 5D-пространстве;

\* $S\_{genre}$ — коэффициент нечёткого совпадения сгенерированных жанровых тегов с базой треков (Sørensen–Dice);

\* $P\_{norm}$ — нормализованный показатель популярности трека в стриминговом сервисе ($\[0.0, 1.0]$).

\## 5. Спецификация REST API



Контракты взаимодействия задокументированы в стандарте OpenAPI 3.0:  

\[Спецификация openapi.yaml](docs/openapi.yaml)



| Метод | Эндпоинт | Описание |

|---|---|---|

| `POST` | `/analyze` | Загрузка изображения, инициализация фонового расчета, выдача `task\_id` |

| `GET` | `/status/{task\_id}` | Polling статуса готовности (`processing` / `completed` / `error`) |

| `GET` | `/result/{task\_id}` | Получение витрины результатов и топ-10 рекомендаций |

| `POST` | `/rate` | Сохранение пользовательской оценки (1-5) и вектора в БД `ratings` |

| `POST` | `/download\_card` | Генерация и стриминг визуальной JPEG-карточки 1080×1080 |

| `POST` | `/download\_csv` | Выгрузка плейлиста в формате CSV (UTF-8-BOM) |

\## 6. Метрики и результаты тестирования



\* \*\*Выборка тестирования:\*\* 100 разнородных изображений (пейзажи, портреты, архитектура, абстракции).

\* \*\*Качество подбора:\*\* Средняя пользовательская оценка — \*\*4.39 / 5.0\*\* (85% оценок — 4 и 5 звезд).

\* \*\*Сходство векторов:\*\* Средний $S\_{hybrid}$ для Топ-1 рекомендаций составил \*\*0.847\*\*.

\* \*\*Оптимизация инференса:\*\* 

&#x20; \* Режим NF4 (4-bit) снизил пиковый VRAM с 6.76 ГБ до 3.01 ГБ (в 2.25 раза).

&#x20; \* Время отклика сократилось с 43.85 с до 24.24 с (в 1.8 раза).

\## 7. Локальный запуск проекта

> **ПРИМЕЧАНИЕ:** В данном репозитории размещена облегченная демо-версия базы данных (`music.db`) на 100 000 композиций (~20 МБ) для быстрого локального запуска "из коробки" без скачивания полных датасетов. Полная версия системы тестировалась на базе объемом 2.5М+ треков.

```bash

\# клонирование репозитория

git clone \[https://github.com/твой-логин/cross-modal-music-curator.git](https://github.com/твой-логин/cross-modal-music-curator.git)

cd cross-modal-music-curator



\# установка необходимых зависимостей

pip install -r requirements.txt



\# инициализация структуры таблиц базы данных в каталоге с исходным кодом

sqlite3 src/music.db < db/schema.sql



\# переход в каталог приложения и запуск веб-сервера uvicorn

cd src

uvicorn main:app --host 127.0.0.1 --port 8000 --reload
