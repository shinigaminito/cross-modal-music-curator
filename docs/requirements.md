\# спецификация требований к программной системе



\## 1. введение и назначение

настоящий документ описывает функциональные и нефункциональные требования к интеллектуальной веб-системе кросс-модального подбора музыкальных композиций на основе визуального анализа графических изображений\[cite: 2]. целевая аудитория системы — специалисты медиапроизводства, видеомонтажеры, дизайнеры и контент-мейкеры, решающие задачу подбора согласованного аудиовизуального контента\[cite: 2, 3].



\---



\## 2. действующие лица (акторы)

\* \*\*пользователь (user):\*\* единственный внешний актор системы, взаимодействующий с веб-интерфейсом\[cite: 2]. загружает графический файл\[cite: 2], просматривает полученные аналитические характеристики и список треков\[cite: 2], осуществляет переход к прослушиванию на внешних платформах\[cite: 2], экспортирует результаты анализа\[cite: 2] и отправляет оценку качества подбора\[cite: 2].



\---



\## 3. функциональные требования (functional requirements)



\### модуль приема и предобработки контента

\* \*\*fr-01 (валидация формата):\*\* система должна принимать графические файлы исключительно в форматах jpeg и png\[cite: 2, 4]. при передаче файлов других форматов возвращается http-код 400\[cite: 4].

\* \*\*fr-02 (контроль размера):\*\* размер входного файла не должен превышать 10 мб\[cite: 2, 4].

\* \*\*fr-03 (нормализация данных):\*\* графический файл должен автоматически приводиться к цветовому пространству rgb для предотвращения ошибок несовпадения размерностей тензоров\[cite: 2, 4].

\* \*\*fr-04 (масштабирование для инференса):\*\* для ускорения обработки нейросетью должно формироваться уменьшенное представление кадра с максимальным разрешением 1000×1000 пикселей с применением фильтра lanczos\[cite: 2, 4].



\### модуль колористического анализа

\* \*\*fr-05 (экстракция доминирующей палитры):\*\* система должна выделять 5 наиболее частотных цветов кадра с помощью адаптивного квантования библиотеки pillow и транслировать их в hex-формат\[cite: 2, 4].

\* \*\*fr-06 (расчет hsv-метрик):\*\* алгоритм должен вычислять средние арифметические значения каналов hue (тон, 0–360°), saturation (насыщенность, 0–100%) и value/brightness (яркость, 0–100%)\[cite: 2, 4].



\### модуль нейросетевого анализа и трансляции

\* \*\*fr-07 (zero-shot экстракция признаков):\*\* визуально-языковая модель qwen2.5-vl-3b-instruct должна анализировать кадр по системному промпту и формировать валидный json-объект, включающий 5 психоакустических оценок (valence, energy, danceability, acousticness, instrumentalness) в диапазоне \[0.0, 1.0], строку подходящих жанров и текстовую эстетическую интерпретацию\[cite: 2, 4].

\* \*\*fr-08 (гибридная трансляция признаков):\*\* система должна объединять предсказания модели с колористическими метриками кадра по следующим правилам\[cite: 2, 4]:

&#x20; \* $valence = 0.7 \\cdot vlm\\\_valence + 0.3 \\cdot brightness + hue\\\_bias$\[cite: 2, 4]

&#x20; \* $energy = 0.7 \\cdot vlm\\\_energy + 0.3 \\cdot saturation$\[cite: 2, 4]

&#x20; \* $danceability = 0.7 \\cdot vlm\\\_danceability + 0.3 \\cdot saturation$\[cite: 2, 4]

&#x20; \* $acousticness = 0.7 \\cdot vlm\\\_acousticness + 0.3 \\cdot is\\\_warm$\[cite: 2, 4]

&#x20; \* $instrumentalness = vlm\\\_instrumentalness$\[cite: 2, 4]

\* \*\*fr-09 (перевод описания):\*\* текстовая семантическая интерпретация на английском языке должна автоматически переводиться на русский язык библиотекой deep-translator с использованием оригинального текста при ошибках соединения\[cite: 2, 4].



\### модуль векторного поиска и ранжирования

\* \*\*fr-10 (гибридная метрика подобия):\*\* вычисление расстояния между 5d-вектором кадра и характеристиками треков каталога должно совмещать косинусное сходство и нормализованное евклидово сходство\[cite: 2, 4]:

&#x20; $S\_{hybrid} = 0.7 \\cdot S\_{cos} + 0.3 \\cdot \\frac{1}{1 + d}$\[cite: 2, 4]

\* \*\*fr-11 (интегральный скоринг):\*\* итоговый ранжирующий балл должен агрегировать гибридную метрику, нечеткое жанровое совпадение (коэффициент сёренсена-дайса) и популярность композиции\[cite: 2, 4]:

&#x20; $Score\_{total} = 0.75 \\cdot S\_{hybrid} + 0.15 \\cdot S\_{genre} + 0.10 \\cdot P\_{norm}$\[cite: 2, 4]

\* \*\*fr-12 (дедупликация и стохастическая выборка):\*\* из пула 80 лучших кандидатов исключаются дубликаты по паре «исполнитель — трек», после чего случайным образом отбираются 10 финальных композиций с сохранением порядка их релевантности\[cite: 2, 4].



\### модуль взаимодействия, экспорта и обратной связи

\* \*\*fr-13 (внешняя навигация на стриминги):\*\* для каждой рекомендованной композиции система должна динамически формировать прямые поисковые ссылки на youtube, spotify, яндекс музыку и vk музыку\[cite: 2, 4, 8].

\* \*\*fr-14 (экспорт в csv):\*\* по запросу пользователя должен генерироваться файл playlist.csv в кодировке utf-8-bom, содержащий названия треков и имена артистов\[cite: 2, 4].

\* \*\*fr-15 (генерация визуальной карточки):\*\* рендеринг растровой jpeg-карточки фиксированным разрешением 1080×1080 пикселей, включающей размытую подложку исходного кадра, блок hex-палитры и список 10 треков со значениями релевантности\[cite: 2, 4].

\* \*\*fr-16 (фиксация пользовательской оценки):\*\* сохранение рейтинга (от 1 до 5 звезд), 5d-вектора признаков, колористических параметров hsv и сериализованного массива рекомендованных композиций в таблицу `ratings`\[cite: 2, 4].

\## 4. нефункциональные требования (non-functional requirements)



\### производительность и скорость обработки

\* \*\*nfr-01 (время анализа):\*\* полный цикл обработки одного запроса не должен превышать 30 секунд (фактическое среднее значение: 24.57 ± 1.79 с)\[cite: 2, 3].

\* \*\*nfr-02 (асинхронное исполнение):\*\* операции нейросетевого инференса и графического рендеринга должны выноситься в фоновый диспетчер `backgroundtasks` и `threadpoolexecutor`, предотвращая блокировку event loop fastapi\[cite: 2, 4].



\### требования к ресурсам и аппаратному обеспечению

\* \*\*nfr-03 (ограничение vram):\*\* пиковое потребление видеопамяти графического ускорителя не должно превышать 4 гб (фактическое пиковое значение: 3.01 гб за счет 4-битной квантизации normalfloat4)\[cite: 2, 3].

\* \*\*nfr-04 (управление памятью gpu):\*\* принудительный сброс неиспользуемых тензоров (`torch.cuda.empty\_cache()`) до и после каждого сеанса инференса\[cite: 2, 4].

\* \*\*nfr-05 (потокобезопасность инференса):\*\* предотвращение конфликтов при одновременном обращении нескольких запросов к модели за счет синхронизации через `asyncio.lock()`\[cite: 2, 4].



\### надежность, отказоустойчивость и безопасность

\* \*\*nfr-06 (валидация структуры json):\*\* наличие регулярных выражений и fallback-механизма на случай синтаксически невалидного ответа модели с возвратом дефолтного вектора (значения 0.5)\[cite: 2, 4].

\* \*\*nfr-07 (целостность реляционных данных):\*\* схема базы данных должна поддерживать ограничения `primary key`, `not null` и диапазонные проверки `check` для числовых параметров\[cite: 2, 4].

\* \*\*nfr-08 (защита от атак декомпрессии):\*\* проверка структуры графических файлов на уровне библиотеки pillow для предотвращения сбоев типа decompression bomb\[cite: 2].

\## 5. сценарии использования (use cases)



\### uc-01: сквозной кросс-модальный анализ и подбор музыкальных треков

\* \*\*основной актор:\*\* пользователь\[cite: 2].

\* \*\*предусловие:\*\* сервер fastapi запущен\[cite: 4], веса модели qwen2.5-vl-3b-instruct размещены в vram\[cite: 4], каталог `music.db` доступен для чтения\[cite: 4].

\* \*\*основной сценарий:\*\*

&#x20; 1. пользователь переходит на веб-страницу `/` и выбирает графический файл\[cite: 2, 4, 6].

&#x20; 2. пользователь инициирует подбор нажатием кнопки отправки формы (`post /analyze`)\[cite: 2, 4, 6].

&#x20; 3. сервер проверяет mime-тип и размер файла, генерирует уникальный `task\_id`, ставит задачу в `backgroundtasks` и возвращает страницу `loading.html`\[cite: 2, 4].

&#x20; 4. клиентская страница запускает периодический опрос состояния задачи через `get /status/{task\_id}` с шагом в 1.5 секунды\[cite: 2, 4, 7].

&#x20; 5. фоновый процесс производит масштабирование, параллельно запускает колористический анализ и инференс vlm под защитой `asyncio.lock()`\[cite: 2, 4].

&#x20; 6. рассчитывается гибридный 5d-вектор кадра и выполняется ранжирование по каталогу композиций\[cite: 2, 4].

&#x20; 7. статус задачи обновляется на `completed`\[cite: 2, 4, 7].

&#x20; 8. браузер перенаправляет пользователя на маршрут `/result/{task\_id}`, где отображаются визуальные метрики, описание и топ-10 треков\[cite: 2, 4, 7, 8].

\* \*\*исключительный сценарий а (ошибка входного файла):\*\*

&#x20; 1. пользователь передает поврежденный файл, файл недопустимого формата или размером более 10 мб\[cite: 2, 4].

&#x20; 2. валидатор прерывает выполнение и отдает ответ с http-кодом 400\[cite: 4].

\* \*\*исключительный сценарий б (сбой нейросетевого инференса):\*\*

&#x20; 1. в ходе генерации ответа модель выдает поврежденную структуру или происходит ошибка vram\[cite: 2, 4].

&#x20; 2. активируется fallback-обработчик, присваивающий параметрам вектора значение 0.5, статус задачи переводится в `error`, пользователю выводится диагностическое сообщение\[cite: 2, 4, 7].



\### uc-02: переход к прослушиванию на внешних платформах

\* \*\*основной актор:\*\* пользователь\[cite: 2].

\* \*\*предусловие:\*\* отображена страница `/result/{task\_id}` со сформированным списком треков\[cite: 2, 4, 8].

\* \*\*основной сценарий:\*\*

&#x20; 1. пользователь нажимает на иконку одного из сервисов (youtube, spotify, яндекс музыка, vk музыка) в строке выбранной композиции\[cite: 2, 4, 8].

&#x20; 2. браузер открывает новую вкладку с результатами поискового запроса по имени исполнителя и названию произведения\[cite: 4, 8].



\### uc-03: экспорт визуальной карточки плейлиста

\* \*\*основной актор:\*\* пользователь\[cite: 2].

\* \*\*предусловие:\*\* результаты анализа успешно отображены на странице\[cite: 2, 8].

\* \*\*основной сценарий:\*\*

&#x20; 1. пользователь нажимает кнопку «экспорт визуальной карточки данных»\[cite: 2, 4, 8].

&#x20; 2. клиент отправляет запрос `post /download\_card`, содержащий сериализованные данные треков, палитры и base64-строку исходного кадра\[cite: 2, 4, 8].

&#x20; 3. функция генерации в потоковом пуле отрисовывает размытый фон, цветные круги палитры и названия композиций\[cite: 2, 4].

&#x20; 4. сервер отдает бинарный поток `image/jpeg` с заголовком скачивания `music\_card.jpg`\[cite: 2, 4].



\### uc-04: экспорт плейлиста в формате csv

\* \*\*основной актор:\*\* пользователь\[cite: 2].

\* \*\*предусловие:\*\* результаты анализа успешно отображены на странице\[cite: 2, 8].

\* \*\*основной сценарий:\*\*

&#x20; 1. пользователь нажимает кнопку «экспорт данных в csv»\[cite: 2, 4, 8].

&#x20; 2. отправляется запрос `post /download\_csv` с json-списком треков\[cite: 2, 4, 8].

&#x20; 3. сервер преобразует данные в pandas dataframe, очищает дубликаты и формирует csv со структурой «название, исполнитель»\[cite: 2, 4].

&#x20; 4. система возвращает текстовый поток с префиксом `\\ufeff` и заголовком скачивания `playlist.csv`\[cite: 2, 4].



\### uc-05: фиксация пользовательской оценки качества

\* \*\*основной актор:\*\* пользователь\[cite: 2].

\* \*\*предусловие:\*\* пользователь ознакомился с результатами анализа на странице `/result/{task\_id}`\[cite: 2, 4, 8].

\* \*\*основной сценарий:\*\*

&#x20; 1. пользователь кликает по интерактивной шкале из пяти звезд\[cite: 2, 4, 8].

&#x20; 2. скрипт отправляет json-объект на эндпоинт `post /rate` с оценкой от 1 до 5, психоакустическими и колористическими метриками и списком треков\[cite: 2, 4, 8].

&#x20; 3. сервер валидирует значение и асинхронно записывает запись в таблицу `ratings`\[cite: 2, 4].

&#x20; 4. на клиентской странице фиксируется статус подтверждения приема оценки\[cite: 2, 3, 4, 8].
